## 一、记录原则

本志区分五种状态：

| 状态 | 含义 |
| :--- | :--- |
| 已提交 | 存在可定位 Git 提交 |
| 已验证 | 有当次命令、人工验收或产物证据 |
| 历史验证 | 在旧工作目录或旧版本完成，不能代表当前状态 |
| 在研 | 代码或文档正在形成，尚未达到交付门槛 |
| 待确认 | 缺少足够证据或需要用户决定 |

任何旧部署、旧测试数字和口头计划都不能直接写成当前已完成状态。项目志记录里程碑，日常改动进入 `docs/变更记录.md`。

## 二、项目起点：中文本机财务手账

2026-08-01，零钱簿在独立工作目录中开始实现。最初范围已经包含：

- 中文、人民币、日常收支管理；
- React + TypeScript + Vite；
- Dexie / IndexedDB 本机持久化；
- 整数分金额规则；
- 预算、报表、CSV 导入导出；
- 桌面侧栏与移动端底部导航；
- 米白、墨绿、朱红和水墨手账视觉。

这一阶段确立的首要原则是“本机先能用”。云服务不是记账前置条件，用户不启用同步时，账目只留在当前浏览器。

状态：历史实现，源码已于 2026-08-09 迁入当前仓库。

## 三、阿砚与可选同步

2026-08-02，项目形成两项扩展能力。

第一项是阿砚。它作为水墨砚貅账灵常驻页面，根据本机账簿回答本月支出、预算余额、最近流水和购买判断，也能记住用户希望使用的称呼。它不调用云端模型，不评价用户消费。

第二项是可选跨设备同步。同步使用匿名设备身份、Supabase Realtime 和浏览器端 AES-GCM。配对二维码或链接同时承载加入凭证和解密材料，因此被明确视为账簿钥匙。

旧工作目录曾完成 Cloudflare Pages 部署及双浏览器同步验收，并在验收后清理测试流水。这个结论标记为“历史验证”：它证明当时方案跑通，不代表当前仓库、当前依赖和当前线上环境仍已验收。

## 五、空谷式治理模式落地

同日，阿砚复用空谷项目的长期治理模式，但不复制空谷的 Tauri/Python 技术栈或课表业务逻辑。

治理结构如下：

```text
README.md                 对外入口与当前概览
AGENTS.md                 长期协作、安全和完成标准
MEMORY/MEMORY.md          仓库记忆入口
MEMORY/事实.md            当前可验证事实
MEMORY/决策点.md          长期有效决策
MEMORY/待办.md            分级未完成事项
docs/项目说明.md          产品目标、范围与模块职责
docs/状态与质量门禁.md    当前验证矩阵和交付门槛
docs/变更记录.md          每次正式交付的变更账
docs/PROJECT_CHRONICLE.md 里程碑与演进历史
docs/发布检查清单.md      发布前逐项核对
```

这一模式的核心不是多写文档，而是让“现在确认的事实”“为什么这样做”“下一步要做什么”“过去发生了什么”互不混淆。

## 七、关键决策摘要

1. 本机 IndexedDB 是默认主数据源。
2. 金额统一使用整数分。
3. 云同步必须可选、端到端加密，且失败不能影响本机记账。
4. CSV 导入必须预检并由用户确认。
5. 阿砚提供温和、具体的账本帮助，不评判消费。
6. 项目使用事实、决策、待办、项目志和质量门禁分层治理。
7. 版本升级不等于发布，提交、推送、部署和真实数据操作仍需用户当次授权。

完整决策见 [`../MEMORY/决策点.md`](../MEMORY/决策点.md)。

## 十、2026-08-10：1.0.2 P1 质量完善

P1 把验证范围从关键入口扩展到完整的数据修改链路。组件集成测试现在覆盖流水编辑删除、预算新增编辑删除、自定义分类与流水依赖、清空数据、CSV 错误恢复，以及这些动作对应的同步事件。最终测试数为 8 个文件、41 项。

无障碍完善聚焦实际操作：弹窗能自动聚焦、把 Tab 留在对话框内、用 Escape 关闭并把焦点还给触发按钮；关键输入都有可读标签；当前导航、分类选中、预算进度和超支状态不只依赖颜色。趋势与报表同时保留视觉图形和辅助技术可读的数值表。

加载优化先用构建与浏览器证据定位瓶颈。两张实际加载图片从 PNG 合计约 3.74 MB 降为 WebP 合计约 223 kB；首页趋势改为轻量 SVG，报表继续使用 Recharts，但 114.85 kB gzip 的图表块不再在首页预载，只在进入报表后下载。
