## 二、合并门禁

源码改动进入正式交付前，至少满足：

1. 相关业务逻辑有自动化测试或明确人工验证。
2. `npm.cmd test` 实际通过。
3. `npm.cmd run build` 实际通过。
4. 不包含 `.env.local`、密钥、配对材料、真实账目或生产用户标识。
5. 受影响文档与当前实现一致。
6. 界面改动完成桌面和 375px 视口检查。

## 三、财务数据门禁

出现以下任一情况，不得交付：

- 金额在持久化层使用浮点元；
- CSV 静默忽略非法行或重复写入；
- 日期转换可能产生 UTC 跨日；
- 删除或编辑后汇总、预算或同步事件不一致；
- IndexedDB schema 变化没有升级路径；
- 测试触碰真实浏览器账目。

## 四、同步安全门禁

修改 `src/sync/` 或 `supabase/schema.sql` 时，必须针对性覆盖：

- 加密往返、错误密钥和损坏密文；
- 每条消息使用唯一 IV；
- 离线队列、重复事件和多设备冲突；
- 未授权用户不能读取房间、成员和同步事件；
- 授权成员只能执行协议允许的操作；
- 同步失败不影响本机记账和已确认数据。

未完成这些验证时，只能表述为“代码已实现”或“静态检查通过”，不能表述为“同步安全已验证”。

## 五、发布门禁

发布前需要记录：

- 应用版本和 Git 提交；
- 构建命令、Node/npm 版本和操作系统；
- 产物文件名、大小和 SHA-256；
- ZIP 根目录与正斜杠资源条目检查；
- 桌面、375px、控制台和关键功能验收；
- 环境变量只含公开客户端可用的 Publishable Key；
- 生产配对材料和测试流水已清理。
